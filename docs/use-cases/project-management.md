# 프로젝트 저장/불러오기 유즈케이스

## 목적

사용자는 편집 작업을 프로젝트 단위로 관리하고, 나중에 다시 열어 이어서 작업한다. 별도의 "저장" 동작은 없다 — 프로젝트는 만드는 즉시 저장되어 참조가 생기고, 이후 변경도 즉시 반영된다. 하나의 프로젝트 안에 여러 결과물(통합본 + 여러 하이라이트)을 시퀀스 단위로 나눠 관리한다.

## 사용자 흐름

1. 앱을 켜면 시작 창에 프로젝트 목록(최근 수정 순)이 나타난다. 목록이 비어 있으면 "새 프로젝트 만들기"를 안내한다.
2. 사용자가 새 프로젝트를 만들면 즉시 저장되고, 빈 타임라인(시퀀스) 하나로 편집 창이 열린다. 목록에서 기존 프로젝트를 골라 열 수도 있다.
3. 작업 내용(가져온 클립, 타임라인 구성, 자막, 적용한 이펙트 등)은 바뀌는 즉시 자동 저장된다. 사용자가 저장 명령을 실행할 필요는 없다.
4. 통합본 외에 별도 하이라이트가 필요하면, 같은 프로젝트 안에 새 시퀀스를 추가해 독립적으로 구성한다.
5. 앱을 종료했다가 다시 열면, 마지막 상태(모든 시퀀스, 클립 배치, 재생 위치 등)가 그대로 복원된다.
6. 여러 시퀀스 중 하나를 선택해 전환하며 작업한다.

## 수용 기준

- 별도의 저장 동작 없이, 만든 프로젝트와 그 안의 변경이 즉시 저장된다.
- 프로젝트를 다시 열면 클립 배치·트림·자막·이펙트가 그대로 복원된다.
- 프로젝트 파일은 SwiftData 기반 자체 포맷으로 저장된다(다른 NLE와의 상호운용성은 요구사항이 아님 — [기능명세서](../video-editing-functional-spec.md) 공통 개념 참고).
- 한 프로젝트 안에 여러 시퀀스를 만들 수 있고, 시퀀스 간 전환이 클립 데이터를 공유한다(같은 클립을 여러 시퀀스에서 재사용 가능).
- 시퀀스를 삭제해도 프로젝트 패널의 원본 클립은 남아있다.
- 앱이 예기치 않게 종료돼도 종료 직전 변경까지 복구된다.

## 엣지 케이스

- 시퀀스 하나에서만 쓰던 클립을 프로젝트 패널에서 삭제하면, 그 클립을 참조하던 시퀀스는 어떻게 되는가.
- 프로젝트 파일이 다른 Mac으로 옮겨졌는데 원본 미디어 파일 경로가 달라진 경우(파일 재연결 흐름 필요) — [파일 접근 권한(샌드박스)](../file-access-and-sandboxing.md) 참고.
- 저장 중 앱이 강제 종료되면 프로젝트 파일이 손상되지 않는지.

## 관련 커맨드/쿼리

- 커맨드: `createProject(named:)`(만드는 즉시 저장), `addSequence(name:)`, `deleteSequence(id:)`, `relinkMedia(clip:newURL:)`
- 쿼리: `projectSummaries() -> [ProjectSummary]`(최근 수정 순), `project(id:) -> Project?`, `sequences() -> [EditSequence]`, `unresolvedMediaReferences() -> [Clip]`

## 미정 사항

- 변경을 즉시 저장하기로 했으므로, [환경설정](preferences.md)의 "자동 저장 주기" 항목이 여전히 필요한지(예: 디스크 쓰기 묶음 간격으로 의미를 바꿀지, 항목을 없앨지)
- 파일 재연결(원본 경로가 바뀐 경우) UX
