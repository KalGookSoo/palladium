# 프로젝트 저장/불러오기 유즈케이스

## 목적

사용자는 편집 작업을 프로젝트 단위로 관리하고, 저장한 뒤 나중에 다시 열어 이어서 작업한다. 새 프로젝트는 만드는 즉시 목록에 저장되어 참조가 생기고, 이후 내용 변경은 사용자가 저장(⌘S)해야 반영된다. 하나의 프로젝트 안에 여러 결과물(통합본 + 여러 하이라이트)을 시퀀스 단위로 나눠 관리한다.

## 사용자 흐름

1. 앱을 켜면 시작 창에 프로젝트 목록(최근 수정 순)이 나타난다. 목록이 비어 있으면 "새 프로젝트 만들기"를 안내한다.
2. 사용자가 새 프로젝트를 만들면 즉시 저장되고, 빈 타임라인(시퀀스) 하나로 편집 창이 열린다. 목록에서 기존 프로젝트를 골라 열 수도 있다.
3. 작업 내용(가져온 클립, 타임라인 구성, 자막, 적용한 이펙트 등)이 바뀌면 저장하지 않은 변경으로 표시된다(파일 > 저장 메뉴 활성화, 창 닫기 버튼의 점). 사용자는 메뉴 바의 파일 > 저장(⌘S)으로 저장한다. 편집 창 안에는 저장 버튼을 두지 않는다.
4. 저장하지 않은 채 창을 닫거나 앱을 종료하면 "변경 사항을 저장하시겠습니까?"를 묻는다.
5. 저장하지 않은 변경은 주기적으로 별도 백업본에 기록되고, 비정상 종료 후 다시 열면 복구를 제안한다.
6. 통합본 외에 별도 하이라이트가 필요하면, 같은 프로젝트 안에 새 시퀀스를 추가해 독립적으로 구성한다.
7. 앱을 종료했다가 다시 열면, 마지막으로 저장한 상태(모든 시퀀스, 클립 배치 등)가 그대로 복원된다.
8. 여러 시퀀스 중 하나를 선택해 전환하며 작업한다.

## 수용 기준

- 새 프로젝트는 만드는 즉시 목록에 저장되고, 이후 변경은 메뉴 바의 파일 > 저장(⌘S)으로 저장한다(편집 창 안에 저장 버튼은 없다).
- 저장하지 않은 변경이 있을 때만 파일 > 저장 메뉴가 활성화되고, 창 닫기 버튼에 변경 표시가 나타난다.
- 저장하지 않은 채 창을 닫거나 앱을 종료하면 [저장] [저장 안 함] [취소]를 묻는다.
- 프로젝트를 다시 열면 마지막으로 저장한 클립 배치·트림·자막·이펙트가 그대로 복원된다.
- 프로젝트 파일은 SwiftData 기반 자체 포맷으로 저장된다(다른 NLE와의 상호운용성은 요구사항이 아님 — [기능명세서](../video-editing-functional-spec.md) 공통 개념 참고).
- 한 프로젝트 안에 여러 시퀀스를 만들 수 있고, 시퀀스 간 전환이 클립 데이터를 공유한다(같은 클립을 여러 시퀀스에서 재사용 가능).
- 시퀀스를 삭제해도 프로젝트 패널의 원본 클립은 남아있다.
- 앱이 예기치 않게 종료돼도 마지막 백업 시점까지의 저장하지 않은 변경을 복구할 수 있다.

## 엣지 케이스

- 시퀀스 하나에서만 쓰던 클립을 프로젝트 패널에서 삭제하면, 그 클립을 참조하던 시퀀스는 어떻게 되는가.
- 프로젝트 파일이 다른 Mac으로 옮겨졌는데 원본 미디어 파일 경로가 달라진 경우(파일 재연결 흐름 필요) — [파일 접근 권한(샌드박스)](../file-access-and-sandboxing.md) 참고.
- 저장 중 앱이 강제 종료되면 프로젝트 파일이 손상되지 않는지.

## 관련 커맨드/쿼리

- 커맨드: `createProject(named:)`(만드는 즉시 목록에 저장), `deleteProject(id:)`(프로젝트·내용·백업본 영구 삭제, 원본 파일은 그대로), `ProjectEditor.save()`(열린 프로젝트 저장 후 백업본 삭제), `ProjectEditor.writeBackupIfNeeded()`, `ProjectEditor.discardBackup()`, `ProjectEditor.addSequence(named:)`·`renameSequence(_:to:)`·`deleteSequence(_:)`·`switchToSequence(_:)`(도메인 `Project.addSequence`·`renameSequence`·`deleteSequence`), `relinkMedia(clip:newURL:)`
- 쿼리: `projectSummaries() -> [ProjectSummary]`(최근 수정 순), `project(id:) -> Project?`, `ProjectEditor.hasUnsavedChanges`, `sequences() -> [EditSequence]`, `unresolvedMediaReferences() -> [Clip]`

## 결정 사항(여러 시퀀스, #37)

- 타임라인 머리의 시퀀스 이름을 누르면 메뉴가 열린다: 시퀀스 목록(현재 시퀀스에 체크, 고르면 전환) · 새 시퀀스 · 이름 변경… · 삭제…(확인 창, 마지막 남은 시퀀스는 비활성).
- 새 시퀀스는 빈 시퀀스로 끝에 추가되고 바로 현재 시퀀스가 된다. 이름은 "시퀀스 N"이고 나중에 바꾼다.
- 현재 시퀀스는 편집기(`ProjectEditor.currentSequenceID`)가 들고, 클립 배치·이동·삭제·자르기는 현재 시퀀스에만 적용된다. 현재 시퀀스는 저장하지 않으며 프로젝트를 열면 첫 시퀀스로 시작한다.
- 추가·이름 변경·삭제는 저장하지 않은 변경이 되고 실행 취소할 수 있다. 시퀀스 전환은 프로젝트 내용을 바꾸지 않는다.
- 시퀀스별 화면비 같은 설정은 아직 두지 않는다(화면비는 툴바의 프로젝트 전체 값).

## 결정 사항(프로젝트 삭제, #35)

- 시작 창에서 확인 창을 거쳐 바로 영구 삭제한다. 휴지통처럼 되돌리는 기능은 두지 않는다 — 원본 미디어 파일은 지우지 않으므로, 잃는 것은 편집 내용뿐임을 확인 창에서 알린다.
- 삭제한 프로젝트의 편집 창이 열려 있으면 그 창은 그대로 두고, 저장하려 하면 "저장하지 못했습니다" 오류가 난다(저장소에 없는 프로젝트). 시작 창이 편집 창 상태를 알지 못해 막지 않는다.

## 미정 사항

- [환경설정](preferences.md)의 "자동 저장 주기"는 저장하지 않은 변경을 백업본에 기록하는 주기로 쓴다. 기본값은 백업 구현 시 정한다.
- 파일 재연결(원본 경로가 바뀐 경우) UX
