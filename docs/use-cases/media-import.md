# 미디어 가져오기 유즈케이스

## 목적

사용자는 영상/음악/이미지 파일을 프로젝트로 가져와 정리하고, 필요할 때 타임라인에 배치한다.

## 사용자 흐름

1. 사용자가 Finder에서 파일을 앱 창으로 드래그&드롭하거나, 파일 선택 대화상자로 하나 이상의 파일을 고른다.
2. 앱이 각 파일의 포맷/코덱을 확인한다([지원 미디어 포맷/코덱](../media-format-support.md) 참고).
3. 지원하는 파일은 프로젝트 패널에 추가되고, 자동으로 썸네일/길이 같은 메타데이터를 표시한다.
4. 원본 해상도가 4K 이상이면 자동으로 프록시(저해상도 대체 파일)를 생성해 연결한다 — 그 이하 해상도는 원본을 그대로 쓴다([환경설정](preferences.md)에서 이 임계값을 바꿀 수 있다).
5. 지원하지 않는 파일은 목록에 추가하지 않고, 어떤 파일이 왜 실패했는지 안내한다.
6. 사용자는 포토샵에서 레이어를 정리하듯 프로젝트 패널에서 클립 이름을 직접 바꾸고, 폴더(빈)로 분류하거나 색상 레이블·태그를 붙인다.
7. 클립이 많아지면 이름/태그/레이블로 검색·필터링해 원하는 클립을 찾는다.
8. 프로젝트 패널의 클립을 타임라인으로 드래그해 배치한다(실제 배치 이후 동작은 [클립 이어붙이기](joining-clips.md) 참고).

## 수용 기준

- 드래그&드롭과 파일 선택 대화상자 두 경로 모두로 가져오기가 가능하다.
- 여러 파일을 한 번에 선택해 가져올 수 있다.
- 가져온 클립의 이름을 바꾸고(원본 파일 이름은 그대로), 폴더로 분류하거나 색상 레이블·태그를 붙일 수 있다.
- 클립 이름/태그/레이블 기준으로 검색·필터링할 수 있다.
- 지원하지 않는 포맷을 가져오려 하면, 어떤 파일이 문제인지 구체적으로 안내한다(일부만 실패해도 나머지는 정상 처리).
- 4K 이상 해상도의 원본은 가져올 때 자동으로 프록시(저해상도 대체 파일)를 생성해 연결한다(기본값) — 그 이하 해상도는 원본을 그대로 사용해 불필요한 대기시간·디스크 사용을 만들지 않는다.
- 프록시 생성 여부를 가르는 해상도 임계값은 [환경설정](preferences.md)에서 바꿀 수 있다.

## 결정 사항

- 원본은 복사하지 않고 제자리에서 참조한다. 앱을 다시 켜도 열 수 있도록 원본마다 security-scoped bookmark를 함께 저장한다([파일 접근 권한](../file-access-and-sandboxing.md)).
- 이미 가져온 파일(같은 경로)을 다시 가져오면 추가하지 않고 기존 원본을 선택한 뒤, 몇 개를 건너뛰었는지 알린다.
- 파일 단위로만 가져온다. 폴더를 끌어오면 "폴더는 가져올 수 없습니다"로 안내한다.
- 가져온 원본은 미디어 패널의 "분류 안 됨"에 추가되고, 저장하지 않은 변경이 된다(파일 > 저장으로 반영).
- 이미지는 길이가 없어 타임라인에 처음 놓을 때 5초로 놓는다(`MediaAsset.stillImageDuration`). 미디어 패널 행에는 길이 대신 "이미지"로 보여주고, 더블클릭하면 훑어보기 창으로 본다(#50, #5).
- 이름은 포토샵 레이어처럼 목록 안에서 바로 바꾼다: 원본을 고르고 F2(편집 > 이름 변경, 미디어 패널 목록에 포커스가 있을 때) 또는 우클릭 > 이름 변경. Return으로 확정, Esc로 취소, 다른 곳을 누르면 확정한다. 바꾼 이름은 프로젝트 안에서만 쓰고 원본 파일 이름은 바꾸지 않는다. 비우면 바꾸지 않는다. 영상·오디오 항목을 두 번 누르거나 ⌘T(우클릭 > 트림…)로 트림 시트를 열어 쓸 구간만 골라 "새 항목으로 저장"하거나 "자르기"로 나눠 파생 항목을 만든다(#81, 원본 항목·파일은 바꾸지 않음 — [클립 자르기](trimming.md) 결정 사항). 미디어 패널에서 두 번 누르면 영상·오디오는 트림 시트, 이미지는 훑어보기를 연다(원본 파일 전체는 우클릭 > 훑어보기). 원본 이름은 재료 정리와 새 클립의 기본 이름용이고, 타임라인 클립마다 다른 이름은 클립 별칭(#78, [클립 이어붙이기](joining-clips.md))으로 단다.
- 정리 정보는 색상 레이블(Finder 태그와 같은 일곱 색 중 하나)과 태그(쉼표로 나눠 입력하는 자유 텍스트)다. 미디어 패널에서 원본을 우클릭해 바꾸고, 행에는 색 점과 "길이 · 태그"로 보여준다. 별점은 처음 기능명세서에 있었지만 쓸 일이 적어 넣지 않는다.
- 검색창은 이름과 태그를 함께 찾는다. 검색창 아래 필터 메뉴로 색상 레이블(여러 개 고르면 그중 하나)을 고르며, 검색어와 레이블을 모두 만족하는 원본만 보인다.
- 폴더(#24, #93에서 트리로): 미디어 패널은 **하나의 폴더 트리**다. 맨 위 단계(프로젝트)에 폴더와 어느 폴더에도 없는 원본이 함께 보이고, "분류 안 됨" 묶음은 없앴다(#93 사용자 요청 — 묶음 머리가 필요 없고 Finder처럼 보이길 원함). 폴더 안에 폴더를 깊이 제한 없이 두고, 폴더마다 펼침 삼각형으로 접고 편다.
  - 만들기: 위쪽 새 폴더 버튼은 폴더 하나를 골랐으면 그 안에, 원본 하나를 골랐으면 그 원본이 있는 폴더 안에, 아니면 맨 위에 만든다. 폴더 우클릭 > 새 폴더로 그 안에 만든다. 만들면 부모를 펼치고 바로 이름을 묻는다.
  - 옮기기: 원본(여러 개)이나 폴더 머리를 끌어 다른 폴더 머리·그 폴더 안 원본 위에 놓으면 그 폴더 안으로, 맨 위 원본 위나 목록 빈 곳에 놓으면 맨 위로 옮긴다(실행 취소 한 번). 폴더는 자기 자신이나 자기 아래 폴더로는 옮기지 않는다(편집도 남지 않음). 끄는 동안 접힌 폴더 머리 위에 0.7초 머물면 펼친다. 원본은 한 폴더에만 속한다.
  - 놓을 곳 표시(#109): 끄는 동안 놓으면 들어갈 곳을 보여준다. 폴더로 들어가면(그 폴더 머리 위, 또는 그 폴더 안 원본 위) 그 폴더 머리를 강조색으로 칠하고 아이콘을 채운 폴더로 바꾸며, 맨 위로 가면(맨 위 원본 위, 목록 빈 곳) 목록 테두리에 강조색 윤곽선을 그린다. 목록 아래 띠에 "'폴더 이름' 폴더로 이동"·"맨 위로 이동" 안내 글자도 보인다. 원본 줄 위에 놓으면 그 원본의 폴더로 들어가는데 커서는 원본 위에 있어 폴더 안인지 밖인지 헷갈린다는 사용자 요청. 끄는 내용은 놓기 전에는 알 수 없어, 이미 그 폴더에 있어 아무 일도 없는 경우나 Finder에서 끈 파일(가져오기)도 같은 표시가 나온다.
  - 끄는 중 자동 스크롤(#108): 원본이 많아 목록에 스크롤이 생기면, 끄는 동안 위쪽 필터 줄이나 목록 아래 끝 띠(24pt)에 커서를 대면 그쪽으로 저절로 굴러간다. 띠의 바깥 끝에 가까울수록 빠르고, 띠를 벗어나면 멈춘다. 띠에 놓으면 아무 일도 하지 않는다. 맨 아래 원본을 맨 위 폴더로 옮기기 어렵다는 사용자 요청. SwiftUI 목록은 점 단위 스크롤이 없어 목록의 `NSScrollView`를 직접 움직인다.
  - 잘라내기·복사·붙여넣기(#104): 미디어 패널에 포커스가 있으면 ⌘X·⌘C·⌘V(편집 메뉴)가 원본에 동작하고, 원본 우클릭에도 같은 항목이 있다. 타임라인 클립보드와 섞이지 않게 미디어 패널은 표시가 붙은 글자(`AssetClipboardPayload`)를 시스템 클립보드에 담는다. 붙이는 곳은 우클릭한 폴더 안(원본을 우클릭하면 그 원본의 폴더), ⌘V면 고른 폴더 안(폴더 하나를 골랐을 때, #107) 또는 고른 원본의 폴더, 고른 것이 없으면 맨 위다.
    - 잘라내기 뒤 붙여넣기는 옮기기이고, 붙인 뒤 클립보드를 비운다.
    - 복사 뒤 붙여넣기는 **사본**을 만든다(사용자 결정 — 말 그대로 사본). 같은 파일을 가리키는 항목이라 디스크 파일은 복사하지 않고(원본 파일은 바꾸지 않는 원칙), 구간·크롭·색상 레이블·태그가 같다. 이름이 겹치면 " (1)"·" (2)"…를 붙인다(예: "윈드밀1 (1).mov"). 파생 항목처럼 처음 원본의 키를 같이 써 썸네일·프록시를 다시 만들지 않아 "파생" 표시가 붙고, 클립 편집 창에서 구간을 다시 정할 수 있다. 실행 취소 한 번.
    - "폴더로 이동" 하위 메뉴는 없앴다(사용자 결정 — 끌어 놓기와 잘라내기·붙여넣기로 충분하고 폴더가 많으면 메뉴가 길어진다).
  - 우클릭 메뉴(#104): 원본은 새 폴더(그 원본의 폴더 안)·잘라내기·복사·붙여넣기·색상 레이블…, 폴더는 새 폴더(그 안)·붙여넣기·이름 변경·삭제(폴더를 여러 개 골라 우클릭하면 삭제만), 목록 빈 곳은 새 폴더(맨 위)·가져오기…(⌘I)·붙여넣기.
    - 폴더 ID도 원본 ID와 같은 `UUID`라 목록이 폴더 줄도 고르고, 목록 전체의 우클릭 메뉴가 폴더 머리의 메뉴보다 먼저 뜬다. 그래서 목록 메뉴가 받은 ID가 모두 폴더면 폴더 메뉴를 낸다(#107 — 폴더를 우클릭해도 원본 메뉴가 떠 이름 변경·삭제가 안 되던 버그). 폴더를 고르고 F2(편집 > 이름 변경)를 누르면 폴더 이름을 묻는다. 원본과 폴더를 섞어 고르면 원본 메뉴이고, 끌기·잘라내기·복사에는 함께 고른 폴더를 넣지 않는다.
  - 지우기: 폴더 우클릭 > 폴더 삭제, 또는 폴더를 고르고 ⌫. 안의 원본과 하위 폴더는 한 단계 위로 올라가고(맨 위 폴더면 맨 위로), 실행 취소할 수 있어 확인 창은 띄우지 않는다.
  - 접고 편 상태: 프로젝트 내용이 아니라 보기 상태라 앱 설정(`UserDefaults`, 접은 폴더 ID)에 두어 앱을 다시 켜도 유지한다. 접고 펴도 저장하지 않은 변경·실행 취소가 생기지 않는다(이슈에는 "폴더에 저장"이라 적었지만, 접기만 해도 저장 표시가 켜지는 문제 때문에 바꿨다).
  - 검색·필터 중에는 그 아래 어딘가에 맞는 원본이 있는 폴더만, 모두 펼친 채로 보인다(접힌 상태는 기억해 두었다가 거르기를 풀면 돌아간다). 거르는 중이 아니면 빈 폴더도 보여 놓을 곳이 된다.
  - 저장: `MediaFolderRecord.parentID`(옵셔널)라 한 단계 폴더만 있던 기존 프로젝트도 그대로 열리고 그 폴더들은 맨 위 폴더가 된다. 도메인: `Project.subfolders(of:)`·`folderTree`·`moveFolder(_:into:)`·`folderPath(_:)`, 끄는 폴더는 `FolderDragPayload`.
  - 사이드바 최대 폭은 가장 깊은 폴더 깊이만큼 늘어난다(맨 위 폴더만 있으면 480pt, 한 단계마다 20pt, 상한 720pt — 긴 이름을 보려고 처음 320·560에서 늘림, `MainWindowMetrics.sidebarMaxWidth(folderDepth:)`). 폭은 저절로 바뀌지 않고 경계를 끌어 더 넓힐 수 있을 뿐이며, 긴 폴더 이름은 가운데를 줄인다. 원본·폴더 줄에 커서를 올리면 전체 이름이 툴팁으로 보인다.
- 정렬(사용자 결정, #94): 폴더끼리, 폴더 안, 맨 위 원본 모두 **이름 오름차순**이고 한 폴더 안에서는 하위 폴더가 먼저다(Finder처럼 숫자는 크기대로 "2" < "10", 대소문자 무시). 그래서 끌어서 순서를 바꾸는 기능은 없앴다(이전에는 폴더 안 원본 위에 놓으면 그 앞에 들어갔다).
- 여러 원본 고르기(#86): ⌘ 클릭으로 하나씩 더하거나 빼고, ⇧ 클릭으로 범위를, 목록에 포커스가 있을 때 ⌘A로 보이는 원본 전체를 고른다. 고른 원본 중 하나를 끌면 고른 원본이 모두 함께 움직인다(폴더 머리·폴더 안 원본 위·맨 위·타임라인). 고르지 않은 원본을 끌면 그 원본만 움직인다. 순서는 **⌘ 클릭한 순서**이고, ⇧ 클릭·⌘A로 한꺼번에 고른 범위는 목록에 보이는 순서로 친다(타임라인에 이어 붙이는 순서. 폴더 안은 이름순으로 보인다). 우클릭 > 잘라내기·복사·색상 레이블·삭제는 고른 원본 모두에, 이름 바꾸기(F2)·태그 편집·클립 편집(⌘T)은 하나만 골랐을 때만 한다. 미디어 패널 선택과 타임라인 클립 선택은 서로 독립이다. 끄는 내용은 원본 ID를 줄마다 하나씩 담은 글자(`AssetDragPayload`)다.
- 타임라인 클립 안에는 내용을 그린다(#31): 영상·이미지 클립은 클립 높이에 맞춘 16:9 칸마다 그 구간 가운데 프레임(필름스트립), 오디오 클립은 막대 파형. 줌으로 칸·막대 개수가 바뀔 때만 다시 만들고, 프레임은 30분의 1초 단위로, 파형은 원본마다 초당 100개로 메모리에 캐시한다(`ClipContentProvider`). 만들지 못하면 비워 두고 이름 옆 종류 아이콘이 남는다. 미디어 패널 썸네일 캐시(`MediaThumbnailProvider`)와는 따로 두되 이미지 클립은 그 썸네일을 쓴다.
- 미디어 패널 행에는 썸네일을 보여준다. 영상은 1초 지점(1초보다 짧으면 가운데) 한 장면, 이미지는 축소본이고, 오디오는 아이콘으로 둔다(파형은 #31). 썸네일은 프로젝트에 저장하지 않고 앱이 켜져 있는 동안 메모리에만 둔다(`MediaThumbnailProvider`). 만들지 못하면(파일 없음 등) 종류별 아이콘을 보여준다.
- 원본 삭제(#60): [원본 삭제](media-removal.md) — 미디어 패널에서 ⌫·우클릭 > 삭제, 쓰이는 원본은 클립도 함께 지운다는 확인 후 삭제, 원본 파일은 남는다.
- 프록시(#43): 가져온 영상의 화면 크기(회전 반영) 짧은 변이 환경설정의 기준(기본 4K = 2160 이상, 1440p 이상, 만들지 않음) 이상이면 뒤에서 1080p 이하 H.264 대체 파일을 만든다. 프로젝트에 저장하지 않는 앱 캐시라 앱 컨테이너 Application Support/Proxies/<원본 ID>.mov에 두고, 파일이 있으면 프록시가 있는 것으로 본다(다 만든 뒤에 이름을 바꿔 넣어 반쯤 만든 파일은 쓰지 않는다).
- 프록시를 만드는 동안에도 원본으로 바로 배치·재생할 수 있고, 다 만들면 미리보기가 다시 합성되며 프록시로 바뀐다. 내보내기·정지 프레임은 항상 원본으로 한다. 미디어 패널 행에 진행률과 "프록시" 표시가 보이고, 영상 우클릭 > 프록시 만들기(기준과 상관없이)·프록시 삭제가 있다. 만드는 일은 실행 취소 대상이 아니다.

## 결정 사항(#110~#116 Finder식 미디어 패널)

- 단축키는 미디어 패널에 포커스가 있을 때만 동작하고(파일·편집 메뉴 항목이 꺼짐), 우클릭 메뉴에도 같은 키를 보여준다.
- 새 폴더 ⇧⌘N(#110): 새 폴더 버튼과 같은 곳(고른 폴더 안 → 고른 원본의 폴더 → 맨 위)에 만들고 바로 이름을 묻는다. 선택 항목으로 새 폴더 ⌃⌘N: 고른 원본·폴더를 담은 새 폴더를 처음 항목이 있던 곳(폴더면 그 부모, 원본이면 그 폴더)에 만들고 이름을 묻는다. 실행 취소 한 번.
- ⌥ 끌기 복사(#111): 놓을 때 ⌥가 눌려 있으면 옮기지 않고 사본(⌘C·⌘V와 같은 사본 규칙)을 만든다. 끄는 동안 ⌥를 누르면 아래 안내가 "…폴더로 복사"·"맨 위로 복사"로 바뀐다. 폴더는 ⌥를 눌러도 옮기기만 한다. 커서의 + 표시는 시스템에 맡겼다(직접 그리지 않음).
- Finder에서 보기 ⌘R(#112): 고른 원본의 파일을 Finder에서 골라 보여준다(여러 개면 모두, 파생 항목·사본은 같은 원본 파일). 파일이 없으면 이름과 함께 알린다. 파생 항목·사본 우클릭 > "원본 항목 보기"는 처음 원본 항목을 고르고 그 줄까지 스크롤한다(지웠으면 꺼짐, 타임라인의 "미디어 패널에서 원본 보기"와 같은 방식).
- 키보드 탐색(#113): →는 접힌 폴더를 펼치고 펼친 폴더면 첫 항목으로, ←는 펼친 폴더를 접고 아니면 부모 폴더로, ⌥→/⌥←는 하위 폴더까지 모두 펼치기·접기, ⌘↓는 원본이면 두 번 누르기와 같고 폴더면 펼치기/접기, ⌘↑는 부모 폴더로. ↑/↓는 목록 기본 동작. 목록(NSOutlineView)이 방향키를 먼저 먹지 않도록 편집 창 키 모니터가 먼저 받아 미디어 패널로 넘긴다. 접힘 상태는 지금처럼 앱 설정에 저장한다. 자막을 골라 둔 채 미디어 패널에서 방향키를 눌러도 자막은 움직이지 않는다(자막 옮기기는 미리보기·타임라인에서만).
- 폴더 펼치기(#114): ⌥를 누른 채 펼침 삼각형을 누르면 하위 폴더까지 같은 상태로, 폴더 줄을 두 번 누르면 펼치고 접는다.
- 찾기 ⌘F(#115): 어느 영역에서든 미디어 패널을 열고(가려 두었으면) 검색창에 커서를 둔다. 입력란을 편집 중이면 그 입력란의 찾기에 맡긴다(키 모니터가 넘김). 편집 메뉴에는 "미디어 패널에서 찾기 (⌘F)"로 적어 둔다. Esc는 검색창 기본 동작(글자 지우기)이다.
- 원본 복제 ⌘D(#116): 고른 원본마다 같은 폴더에 사본을 만들고 사본을 고른다(실행 취소 한 번). ⌘D 메뉴 항목 하나가 미디어 패널에 포커스가 있으면 "원본 복제", 아니면 "복제"(타임라인 클립)다(F2와 같은 방식).

## 엣지 케이스

- 같은 파일을 중복으로 가져오면 기존 원본을 재사용한다(위 결정 사항).
- 가져오는 도중 원본 파일이 이동/삭제되면 어떻게 되는가.

## 관련 커맨드/쿼리

- 커맨드(`ProjectEditor`): `importMedia(from:) -> MediaImportReport`, `renameAsset(_:to:)`, `setColorLabel(_:for:)`, `setTags(from:for:)`
- 쿼리(`ProjectEditor`): `asset(id:)`, `assets(matching: MediaFilter) -> [MediaAsset]`
- 폴더(#24): `addFolder(named:)`, `moveAssets(_:toFolder:before:)` 등
- 프록시(#43, 앱 캐시라 `ProxyGenerator`): `generateIfNeeded(for:threshold:)`, `generate(for:)`, `removeProxy(for:)`, `proxyURL(for:)`, 쿼리 `ProxyThreshold.shouldGenerateProxy(pixelSize:)`

## 미정 사항

- 대용량 파일/긴 영상 가져올 때 로딩 UX(백그라운드 처리 여부, 진행률 표시)
- 4K 기준값이 코덱/프레임레이트에 따라서도 조정돼야 하는지(예: 4K 30fps는 문제없지만 4K 60fps는 버벅이는 기기가 있을 수 있음)
