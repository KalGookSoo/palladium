# 원본 삭제 유즈케이스

## 목적

사용자는 테스트용이거나 잘못 가져온 원본을 프로젝트에서 빼서 미디어 패널을 깔끔하게 유지한다(#60).

## 사용 장면

- 시험 삼아 가져온 영상·음원을 정리할 때
- 같은 촬영본을 여러 번 가져왔거나, 쓰지 않기로 한 컷을 치울 때

## 사용자 흐름

1. 미디어 패널에서 원본을 고른다(미디어 패널은 한 번에 하나를 고른다).
2. 목록에 포커스가 있을 때 ⌫를 누르거나 우클릭 > 삭제…를 고른다. 타임라인에 고른 클립이 있어도 목록에 포커스가 있으면 원본을 지운다.
3. 타임라인에서 쓰이지 않는 원본이면 바로 사라진다.
4. 쓰이고 있으면 확인 창이 뜬다.
   > "IMG_0412.mov"를 쓰는 클립 3개(시퀀스 "통합본", "하이라이트")도 함께 지워집니다. 원본 파일은 디스크에 남습니다. [삭제] [취소]
5. 확인하면 원본과 그 클립들이 함께 지워진다. 클립이 있던 자리는 빈 틈으로 남고 뒤 클립은 움직이지 않는다.
6. 마음이 바뀌면 ⌘Z 한 번으로 원본과 클립이 모두 돌아온다.

## 수용 기준

- 디스크의 원본 파일은 절대 지우지 않는다(프로젝트의 참조만 뺀다). 그 원본의 프록시 파일(앱 캐시)은 함께 지운다.
- 원본은 폴더에서도 빠지고, 저장하면 결과가 유지된다.
- 확인 창은 영향받는 클립 수와 시퀀스 이름을 보여준다(편집기 커맨드는 여러 원본을 한 번에 지울 수 있다).
- 원본 삭제와 클립 삭제는 실행 취소 한 번으로 함께 되돌린다.
- 텍스트 입력 중(이름 바꾸기, 검색)에는 ⌫가 글자를 지우고 원본을 지우지 않는다.

## 결정 사항

- 지운 클립 자리는 빈 틈으로 둔다. 리플로 당기면 다른 클립·자막·마스크와의 시간이 어긋나기 때문이다(틈은 뒤 클립을 끌어 메운다).
- 연쇄 삭제는 저장 구조(SwiftData 관계)가 아니라 편집기 커맨드가 처리한다. 클립은 원본을 ID로만 참조한다.
- 삭제한 클립에 걸려 있던 전환은 맞닿은 이웃이 없어지므로 함께 그려지지 않는다.
- 내레이션 녹음 파일도 같은 규칙을 따른다(앱 컨테이너의 파일은 남긴다).

## 관련 커맨드/쿼리

- 커맨드(`ProjectEditor`): `deleteAssets(_:)` — 원본과 그 원본을 쓰는 모든 시퀀스의 클립을 함께 지운다.
- 쿼리: `clipUsage(of:) -> (clipCount: Int, sequenceNames: [String])` — 확인 창 문구에 쓴다.

## 미정 사항

- "사용하지 않는 원본 고르기" 메뉴(타임라인에 없는 원본을 한 번에 고르기) — 정리할 원본이 많아지면 추가한다.
