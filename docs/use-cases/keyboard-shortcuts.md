# 단축키 유즈케이스

## 목적

사용자는 마우스/트랙패드 없이도 재생·트림 같은 핵심 조작을 빠르게 할 수 있도록 고정된 기본 단축키를 제공받고, 어떤 단축키가 있는지 쉽게 알 수 있다. 사용자가 단축키를 직접 재매핑하는 커스텀 키맵은 이번 범위에서 제외한다([기능명세서 보류 섹션](../video-editing-functional-spec.md#보류추후-논의-기능) 참고).

## 사용자 흐름

1. 사용자가 툴바나 인스펙터의 버튼 위에 마우스를 올리면(hover), 툴팁에 해당 동작의 단축키가 함께 표시된다(예: "재생/일시정지 (Space)").
2. 메뉴 바의 각 메뉴 항목에도 표준적으로 단축키가 표시된다(SwiftUI `Commands`가 기본 제공하는 방식).
3. 전체 단축키가 궁금하면 도움말에서 단축키 가이드를 열어 목록을 한 번에 확인한다.

## 수용 기준

- 재생/일시정지, 프레임 단위 이동, 트림 확정 등 핵심 조작에 고정된 기본 단축키가 있다.
- 툴바·인스펙터의 관련 버튼에는 툴팁으로 단축키가 함께 노출된다.
- 도움말(또는 가이드 문서)에서 전체 단축키 목록을 확인할 수 있다.
- 사용자가 단축키를 직접 재매핑하는 기능은 제공하지 않는다 — 항상 고정된 기본값이다.

## 결정 사항

- 단축키와 설명은 `ShortcutGuide` 한곳에서 관리하고, 툴팁과 단축키 목록 창이 같은 내용을 보여준다. 툴팁은 "이름 — 설명 (단축키)" 형식이다(예: "재생/일시정지 — 미리보기를 재생하거나 멈춥니다 (Space)"). 단축키가 없는 버튼은 "이름 — 설명"만 보여준다.

- 재생·타임라인 단축키(Space, ←/→/↑/↓, ⌫, ⇧⌫, ⌘A, ⌘C, ⌘X, ⌘V, Esc, M, T, R)는 메뉴 단축키로 두지 않고 편집 창에서 키 입력을 직접 받는다(`EditorKeyMonitor`). 클립 우클릭 메뉴에는 단축키를 표시만 한다. 수식키가 있는 클립 분할(⌘B)은 편집 메뉴 항목이다. 메뉴 단축키로 두면 검색창·이름 입력란에서 띄어쓰기와 커서 이동까지 가로채기 때문이다. 입력란을 편집 중이거나 미리보기에 원본이 열려 있지 않으면 키를 그대로 넘기고, 편집 창이 여러 개면 앞에 있는 창만 반응한다.
- 같은 키(⌫·⌘A·⌘C·⌘X·⌘V)가 미디어 패널과 타임라인에서 다르게 동작하므로, **마지막으로 누른 패널**이 받는다(#98). 미디어 패널 목록을 누르면 목록이, 미리보기·타임라인을 누르거나 끌면 그 영역이 키보드 포커스를 가져간다(포커스 테두리는 그리지 않는다). 전에는 타임라인 클립을 눌러도 포커스가 목록에 남아, ⌫가 미디어 패널 원본 삭제를 묻거나 아무 일도 하지 않았다.
- 키를 받는 영역은 **미디어 패널·미리보기·타임라인·인스펙터** 넷이다(#103, 사용자 결정). 마지막으로 누른 영역이 키를 받고, 미리보기·타임라인·인스펙터는 그동안 안쪽에 얇은 강조색 테두리가 보인다(Premiere식). 미디어 패널은 목록 선택 색(포커스면 강조색, 아니면 회색)으로 알 수 있다. 타임라인(또는 미리보기)이 키를 받지 않으면 고른 클립·자막·마스크 테두리도 회색이 된다(사용자 결정 — 테두리 + 선택 색).
  - ←/→ 프레임 이동과 자막 옮기기(방향키)는 미리보기·타임라인에서만 한다(사용자 결정 — Premiere·Final Cut처럼 타임라인에서도). 미디어 패널에서는 목록이 ↑/↓(이동)·←/→(폴더 접기·펴기)를 받고, 인스펙터에서는 슬라이더 같은 컨트롤이 받는다.
  - Space(재생)·M·T·R은 입력칸 편집 중이 아니면 어느 영역에서나 동작한다. ⌫·⌘A·⌘C·⌘X·⌘V는 미디어 패널이면 원본, 나머지 영역이면 타임라인 선택에 동작한다.
  - 인스펙터를 누르면 미디어 패널 목록이 쥔 키보드 포커스를 놓게 해, ↑/↓·⌫가 목록으로 가지 않는다(입력칸·슬라이더는 스스로 포커스를 가진다).
  - 타임라인 우클릭 > "미디어 패널에서 원본 보기"는 그 원본을 고르고, 가려 둔 미디어 패널을 열고, 미디어 패널이 키를 받게 한 뒤 그 줄까지 스크롤한다(#101). 접힌 폴더 안이면 펼친다(#93).
- 도움말 > 단축키 목록(⌘/) 또는 palladium 도움말(⇧⌘/)에서 전체 목록을 보고 검색한다(#20).
- #64 단축키 점검(사용자 결정 — Claude가 정하고 사용자가 나중에 검토, Final Cut·Premiere·QuickTime에서 공통으로 쓰는 가장 보편적인 키):
  - J/K/L(세 앱 공통), Home/End(처음·끝), ↑/↓(이전·다음 편집점 — Final Cut·Premiere), ⇧Z(전체 보기 — Final Cut), ⇧←/→ 10프레임(Final Cut), ⌘N 새 시퀀스(Premiere), ⌘[ / ⌘] 이전·다음 시퀀스(Final Cut의 타임라인 기록 이동 자리).
  - 기본 전환은 Final Cut의 ⌘T 자리지만 ⌘T는 QuickTime식 클립 편집(#85, 사용자 결정)이 쓰고 있어 ⇧⌘T로 둔다. Premiere의 ⌘D는 복제(#62)가 쓴다. 기본 전환은 1초 디졸브이고 오디오 크로스페이드는 넣지 않는다.
  - 정지 프레임 저장은 세 앱에 공통 키가 없어 내보내기(⌘E) 묶음의 ⌥⌘E로 둔다.
  - 단축키를 두지 않은 기능: 마스크 추가·트랙 추가·자막 가져오기/내보내기(세 앱에 공통 키가 없고 자주 쓰지 않음), 고른 클립 한 프레임 옮기기(삽입만 하는 타임라인에서는 틈 안에서만 의미가 있어 뺐다).
  - 한 글자 단축키는 입력란 글자를 가로채지 않도록 지금처럼 `EditorKeyMonitor`가 받고, 새 **재생 메뉴**(Space·J/K/L·Home/End·↑/↓·←/→·⇧←/→·R)와 **타임라인 메뉴**(M·T·⇧Z, 그리고 진짜 메뉴 단축키인 ⇧⌘T·⌘[·⌘])에 "이름 (키)"로 적어 찾을 수 있게 한다. 메뉴에서 누르면 키를 누른 것과 같은 일을 하되 키를 받는 영역과 상관없이 실행한다.
  - ↑/↓·⇧←/→·Home/End는 미리보기·타임라인이 키를 받을 때만 동작한다(미디어 패널은 목록 이동, 인스펙터는 컨트롤). 자막을 골랐으면 방향키는 자막을 옮긴다(#82).
  - 거꾸로 재생(J)은 합성이 거꾸로 재생을 지원할 때만 동작한다.
  - `ShortcutGuide.sections`의 키가 서로 겹치지 않는지 테스트로 확인한다. 같은 키를 창마다 다르게 쓰는 항목은 "(클립 편집 창)"·"(시작 창)"처럼 키 문구에 자리를 적는다.

## 엣지 케이스

- 앱 단축키가 macOS 시스템 전역 단축키(예: 스크린샷, Spotlight)와 겹치면 어떻게 되는가.
- 아이콘만 있고 텍스트 라벨이 없는 툴바 버튼의 단축키 정보를 VoiceOver 사용자에게 어떻게 전달하는가.

## 미정 사항

- 최초 실행 시(온보딩) 단축키 가이드를 자동으로 한 번 보여줄지 여부 — [도움말](help.md) 참고
