# App Store 릴리스 노트 템플릿

App Store Connect > 앱 > macOS 앱 버전 > "이 버전의 새로운 기능(What's New in This Version)" 필드에
그대로 옮겨 적을 사용자용 릴리스 노트 템플릿이다. 4000자 제한이 있고, 마크다운·이슈 번호·기술 용어 없이
평범한 문장으로 쓴다.

`.github/RELEASE_TEMPLATE.md`(GitHub 릴리스 노트, 개발자용)와 짝을 이룬다. 릴리스할 때 GitHub 릴리스 노트를
먼저 쓰고, 그중 사용자가 체감할 수 있는 부분만 추려 이 형식으로 다시 써서 App Store Connect에 옮긴다.

## 버전: X.Y.Z

(사용자가 체감할 수 있는 변경 사항을 2~5줄로. 예:)

- 미디어 패널에서 폴더 이름을 바꾸고 지울 수 있습니다.
- 원본을 끌어 옮길 때 어느 폴더로 들어가는지 표시하고, 목록 끝에 대면 저절로 스크롤됩니다.
- 여러 원본을 빈 타임라인에 끌어 놓을 때 클립이 겹쳐 들어가던 문제를 고쳤습니다.
- 자잘한 문제를 고쳤습니다.

## 작성 가이드

- 이슈 번호, 내부 구조, 권한·저장 형식 변경, 테스트 체크리스트처럼 개발자용 내용은 넣지 않는다 — GitHub
  릴리스 노트(`.github/RELEASE_TEMPLATE.md`)에 남긴다.
- 화면에 보이는 이름(메뉴·버튼·인스펙터 탭 이름)과 단축키를 앱과 같게 쓴다(`ShortcutGuide`·`HelpContent`와 같은 말).
- "할 수 있습니다", "고쳤습니다"처럼 사용자가 이해할 수 있는 표현으로 쓴다.
- 기존 프로젝트를 여는 데 영향이 있는 변경(드물다)은 사용자가 알아야 하므로 한 줄로 알린다.
- 최초 출시(1.0)는 이 필드가 없거나 필수가 아니다. 앱 설명(소개 문구)에 기능을 적고, 필드가 보이면
  "처음 출시했습니다" 정도로 짧게 적는다.
- 로케일마다(지금은 한국어만) 따로 쓴다. 영어 로케일을 더하면 번역해 같이 채운다.
