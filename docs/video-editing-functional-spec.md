# palladium 영상 편집 기능명세서 (초안)

## 목적

기존 데스크톱 영상 편집 소프트웨어의 기능을 참고하되, 유튜브·인스타그램용 영상을 편집하는 개인 사용자에게 필요한 기능만 추려낸 경량 네이티브 앱을 만든다. macOS에 설치해 쓰는 데스크톱 앱을 최우선으로 완성하는 것이 현재 목표다.

## 원칙

- tempo와 마찬가지로 네트워크 연결 없이 모든 핵심 기능이 동작해야 한다.
- 계정 인증, 클라우드 동기화, 온라인 소재/마켓플레이스 연동 등 네트워크가 필요한 기능은 MVP에서 전부 배제한다. 추후 별도 논의를 거쳐 선택적으로 추가할 수 있다.
- 클립/타임라인 계산 로직은 View와 분리해 플랫폼 독립적으로 유지한다([테스트 전략](testing-strategy.md) 참고). 아이패드 UI는 지금 만들지 않지만, 나중에 필요해지면 이 로직을 재활용해 별도 View만 새로 설계할 수 있도록 염두에 둔다.
- 엔진의 각 기능은 커맨드(부수효과 있음)와 쿼리(부수효과 없이 값만 반환)를 엄격히 분리해 구현하고, 커맨드의 부수효과는 이름만 보고도 예측 가능해야 한다([Swift 코딩 컨벤션](swift-coding-conventions.md) 참고). 추후 MCP(Model Context Protocol)를 통해 AI 에이전트에 편집 기능을 위임할 수 있도록, 이 원칙을 구현 시작 시점부터 지킨다.

## 범위

아래는 사용자 검토를 거쳐 확정한 palladium MVP 범위다. 검토에서 보류로 분류된 항목은 [보류(추후 논의) 기능](#보류추후-논의-기능) 절로 옮겼다.

### 가져오기 / 미디어 관리

- 영상·오디오·이미지 파일 가져오기(다양한 포맷/코덱)
- 프로젝트 패널(빈/폴더)로 미디어 정리
- 미디어 메타데이터 확인, 레이블/색상 태그, 별점
- 미디어 검색/필터
- 한 프로젝트 안에 여러 시퀀스(타임라인) 관리
- 프록시 미디어 생성/연결(저사양 편집용 저해상도 대체 파일)

### 타임라인 편집 (핵심 NLE)

- 멀티트랙 비디오/오디오 타임라인
- 클립 트림(리플/롤/슬립/슬라이드 편집)
- 클립 자르기(레이저 도구), 복사/붙여넣기
- 삽입(Insert)/덮어쓰기(Overwrite) 편집
- 3점/4점 편집
- 중첩 시퀀스(Nested Sequence)
- 마커
- 스냅
- 오디오-비디오 링크 해제/재연결
- Match Frame
- 클립 속도·재생 방향 조절(느리게/빠르게, 역재생, 타임 리맵)
- 장면 전환 자동 감지(Scene Edit Detection, 온디바이스 ML)

### 트랜지션

- 비디오 트랜지션(디졸브, 와이프 등)
- 오디오 트랜지션(크로스페이드)

### 이펙트 (영상)

- 색보정/색그레이딩(파형·벡터스코프·히스토그램, LUT 적용)
- 기본 트랜스폼(위치/크기/회전/불투명도)
- 키프레임 애니메이션
- 필터형 이펙트(블러, 왜곡, 스타일라이즈 등)
- 크로마키(그린스크린) 합성(Core Image 커스텀 필터로 구현 가능 — 비용 중간 수준으로 판단해 포함)
- 손떨림 보정(온디바이스 분석 기반 안정화)
- 정적 마스킹(고정된 위치/크기의 영역에만 블러·모자이크 등 이펙트 적용 — 피사체를 따라가지는 않음)
- 이펙트 프리셋 저장/재사용

### 이펙트 (오디오)

- 오디오 믹서/트랙 믹서, 서브믹스
- EQ, 리버브 등 기본 오디오 이펙트
- 라우드니스(음량) 정규화

### 텍스트 / 자막 / 그래픽

- 텍스트/타이틀 도구
- 정적 이미지/스티커 오버레이(고정된 위치·크기·불투명도로 얹기)
- 보조 영상(PIP) 오버레이 — 이미지 오버레이와 같은 방식으로, 소스가 영상인 경우(자체 트림 구간을 가짐)
- 수동 자막 삽입/편집, 자막 스타일링
- 자막 파일 가져오기/내보내기(SRT 등)

### 내보내기

- 포맷/코덱/해상도/비트레이트 프리셋
- 유튜브(16:9)/인스타그램(9:16, 1:1) 등 화면비 프리셋
- 배치(큐) 내보내기
- 정지 프레임(스틸 이미지) 추출

### 미리보기

- 재생/스크러빙, 프레임 단위 이동

## 네트워크가 필요해 제외한 기능

- 자동 자막 생성(음성 인식 기반)
- 소셜 미디어(유튜브 등)로 직접 게시(Publish)
- 온라인 소재/마켓플레이스 연동
- 클라우드 프로젝트 동기화, 실시간 협업, 리뷰·코멘트 기능
- 생성형 확장/채우기 등 클라우드 AI 기능

## 보류(추후 논의) 기능

아래 항목은 제외가 아니라 지금 당장 결정하지 않고 미뤄둔 기능이다. 구현 비용이 크거나 범위가 애매해 MVP 우선순위가 정해진 뒤 다시 검토한다.

- 오브젝트 트래킹(피사체를 따라 움직이는 동적 마스킹 — 정적 마스킹과 달리 위치가 자동으로 갱신됨) — 온디바이스 ML 기반 트래킹 구현 비용이 큼. 필요한 기능으로 보고 있으나 정적 마스킹으로 우선 대응하고, 우선순위를 낮춰 계속 보류
- 오디오 노이즈 제거/향상(Enhance Speech류) — 단순 EQ/리버브보다 복잡한 DSP·ML이 필요함
- 오디오 더킹(배경음 자동 감쇠) — 음성/음악 트랙을 구분하는 로직이 필요해 단순 EQ보다 복잡함
- 모션 그래픽 템플릿(재사용 가능한 자막/그래픽 템플릿) — 파라미터화된 콘텐츠 저작 시스템을 새로 만들어야 해 범위가 큼
- 트랜스크립트 기반 편집(음성을 텍스트로 변환해 텍스트 편집하듯 영상 자르기) — 음성인식 모델 + 전용 편집 UI가 필요해 비용이 가장 큼
- 자동 리프레임(피사체 인식 후 화면비 자동 재구성) — ML 비용이 큼

## 공통 개념(추후 구체화)

- 프로젝트: 가져온 미디어(클립 원본)와 하나 이상의 시퀀스를 담는 저장 단위. 저장/재개 가능해야 함([프로젝트 저장/불러오기](use-cases/project-management.md) 참고). 프로젝트 파일 포맷은 SwiftData 기반 자체 포맷으로 결정 — 다른 NLE와의 상호운용성은 요구사항이 아니며, 필요해지면 네이티브 포맷은 그대로 두고 EDL/OTIO 같은 표준 포맷 내보내기 기능을 별도로 추가한다.
- 시퀀스(타임라인): 프로젝트 안의 독립된 편집 결과물 하나(통합본 또는 하이라이트 하나). 여러 트랙을 포함한다.
- 트랙: 시퀀스 안에서 클립들이 순서대로 배치되는 하나의 레인. 영상/오디오 트랙을 여러 개 둘 수 있다(멀티트랙).
- 클립: 원본 미디어 파일 참조 + in/out 트림 지점 + 적용된 이펙트/트랜지션.
